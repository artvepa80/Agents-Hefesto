## Procedimiento después del merge

1. Confirmar CI verde en `main`.
2. `git tag -a v4.16.0 -m <notas> <sha del squash>` y empujar el tag.
3. `release.yml` construye, sube a PyPI, crea la GitHub Release (`--generate-notes`) y
   mueve `v4`. Las notas de la Release se reemplazan por las del borrador (abren con el
   cambio de exit code) seguidas de las generadas.
4. Verificar PyPI (wheel y sdist), que `v4` apunte al commit de 4.16.0 y que `v4.15.1`
   no cambie.
5. Landing privada y demo de Hugging Face a 4.16.0.
6. Probar la Action `@v4` contra un repo sin archivos analizables (solo Markdown y un JS
   vendorizado): exit 1 y mensaje con la causa.
