One table, `hefesto/reports/cwe_map.py` (CWE list 4.20), feeds both SARIF outputs:

| Issue type | CWE | Relationship | Precision |

| SQL_INJECTION_RISK | 89 | superset | (from confidence) |

| PICKLE_USAGE | 502 | relevant | low (import only) |
| BARE_EXCEPT | 396 | equal | (from confidence) |
| ASSERT_IN_PRODUCTION | none | | |

- Rule tag `external/cwe/cwe-N` (GitHub code scanning reads this).
- `run.taxonomies` one CWE component (name `CWE`, organization `MITRE`, version `4.20`) with only the ids used in the run, and `relationships` on each mapped rule (`target.toolComponent.name` = `CWE`).
- `metadata["cwe"]` overrides the table. Digits are copied as written, so COBOL `CWE-20` stays `cwe-20`.
- Unmapped rules emit neither a CWE tag nor a relationship. A run with no CWE omits `taxonomies`.
